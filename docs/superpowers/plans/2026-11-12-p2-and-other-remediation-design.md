# P2 及其他遗留问题修复设计

日期：2026-11-12

## 目标

完整修复 `docs/reviews/2026-11-12-deferred-p2-and-other-findings.md` 中记录的 P2 与其他问题，同时明确保持“首次登录不强制管理员修改密码”的现状。

## 设计原则

1. 状态机结果必须显式表达，不允许用 `void` 或“成功响应信封 + 失败 HTTP 状态”承载不同业务终态。
2. 多实例共享约束必须由数据库事务、行锁或唯一约束保证，不依赖单 JVM 的 `synchronized`。
3. 所有外部 URL、下载凭证和删除许可都按最小权限、短时有效、精确对象身份校验。
4. 列表类接口统一使用稳定分页；前端所有可被后续请求替代的异步请求都使用代次保护。
5. 调度路径禁止逐记录回查和无界历史加载；统计在数据库完成。
6. 敏感操作统一记录操作者、角色、来源地址、目标、结果和失败原因。

## 方案

### 一、数据正确性与状态机

- 空间预留：锁定容量池后，先把该池已过期的 `ACTIVE` 记录原子改为 `EXPIRED`，再统计有效预留并插入新记录。这样既释放唯一键，也保留历史证据。
- 清理任务：`FAILED` 是终态失败，不再计入 pending；存在成功/跳过与失败混合时进入 `PARTIAL`，全部失败也进入 `PARTIAL`。
- 恢复结果：`LocalOrderRestoreService` 返回 `COMMITTED`、`ALREADY_COMMITTED`、`SKIPPED_DELETED` 三种明确结果；任务处理器只把前两种记为成功，把已删除订单记为跳过。
- 竞争失败包：`STATE_CONFLICT` 将暂存记录事务性切换为 `SUPERSEDED + PENDING` 清理状态；后台清理器按卷和存储键幂等删除，失败保留错误与重试次数，定时重试。

### 二、安全与审计

- 外部预签名 URL：引入集中 URI 策略，限制协议、端口、允许域名，解析并拒绝回环、链路本地、站点本地、私网、组播和未指定地址。生产默认不允许任意主机，测试显式放行测试主机。
- 登录防护：使用数据库持久化的用户名摘要 + 客户端地址摘要桶，原子累计失败次数和封禁时间；不存在账号也走同一限流路径，成功后清理对应桶。响应继续保持统一，避免账号枚举。
- 审计归因：集中构造当前操作者上下文，只信任连接的 `remoteAddr`；账号、配置、下载、取消、重试等敏感操作写入完整审计事件。
- 下载：改为认证接口签发短时、单次下载票据，浏览器使用普通导航流式下载；服务端原子消费票据，避免在 JavaScript 堆中完整物化 Blob，也不在 URL 暴露长期登录令牌。
- 删除许可：许可对象同时绑定 `objectKey + versionIdentity`，本地删除前校验冻结集合、许可集合和当前对象版本三者完全一致。

### 三、并发一致性与 API 契约

- 配置修改：在一个数据库事务中锁定全部相关配置行，对投影后的完整配置执行跨项校验，再做乐观版本更新，消除 TOCTOU。
- 健康巡检：只对管理状态允许自动恢复的热备活动/备用卷执行受控目录恢复；管理员离线、冷备和退役卷保持原状态。
- 前端请求：订单、账号和恢复详情分别维护最新请求代次；关闭详情或切换任务会使旧响应失效。
- 401 上传：补传 XHR 的 401 分支必须 reject，并由统一认证失效流程处理。
- 离线下载：HTTP 409 统一返回失败信封及稳定错误码，前端按错误码展示。

### 四、查询与可运维性

- 订单组合筛选：概览条件与普通条件进入同一条动态 SQL，所有条件取交集，统一排序和分页。
- 自动备份：候选、最近失败和已有任务状态改为批量查询；历史窗口设置上限，不再 N+1 或无界加载。
- 冷备封存：主列表数据库分页；文件校验数量使用聚合 SQL，不加载全部校验项。
- 审计：使用 `(occurred_at, id)` 稳定游标分页并提供有上限的导出。
- 集成验证：补充可选的真实 MySQL 多实例测试配置、存储探测演练脚本/说明和负载基线入口；外部 NAS/COS/可移动盘只在显式提供环境时执行。

## 兼容性与迁移

- 新增表/列全部提供独立迁移脚本，并同步全量初始化脚本。
- 旧客户端仍可读取原字段；新增分页接口保留统一 `Page` 数据结构。
- 外部 URL 允许域名和下载票据 TTL 提供配置项；未配置允许域名时外部预签名请求 fail closed，并输出可操作错误。
- 不改变首次登录管理员密码策略。

## 验收标准

- 每个清单项都有自动化回归测试或（仅限真实外设/第三方服务）可重复的显式集成演练入口。
- 后端单元/集成测试、前端测试与生产构建全部通过。
- 新增数据库对象同时存在于增量迁移和全量初始化脚本。
- 最终逐项回查原清单，不留未说明的延期项。
