# 管理概览首页 UI 优化设计

## 目标

把管理概览从纵向堆叠的数据卡片调整为面向值班管理员的态势台，使用户在首屏内确认当前风险、优先处理事项、关键备份指标、存储容量和最近趋势。

## 设计原则

- 保留现有接口、统计口径、异常状态和下钻行为，不增加后端接口。
- 页面只保留一个“管理概览”标题；页面内容区展示数据更新时间和刷新操作。
- 将健康结论和最高优先级告警组合成紧凑的首屏风险区，严重告警直接提供处理入口。
- 关键指标保持可扫读，减少长句，把详细解释留在次级文字中。
- 趋势图与存储面板顶部对齐，不再强制等高；图表获得足够高度和可读字号。
- 存储容量使用横向进度表达已用与剩余，不让普通容量占用率获得超过风险信息的视觉权重。
- 自动化状态和近期活动使用结构化元数据，不展示 `REAL`、`DAYS`、`MINUTES` 等未翻译的内部值。
- 桌面首屏优先，保持现有 1100px 和 700px 响应式降级能力。

## 页面结构

1. 内容工具条：数据更新时间、刷新按钮。
2. 态势风险区：健康结论、最高优先级告警、告警计数和处理入口。
3. 三个核心指标：可恢复订单、本地备份资产、今日备份结果。
4. 近 7 日趋势与存储态势：顶部对齐、各自按内容高度展示。
5. 自动化状态与近期活动。

## 非目标

- 不改变后端统计与告警判定。
- 不引入新的图表库或动画库。
- 不重构全站导航和其他业务页面。
- 不在本次任务中创建 Git 提交。

## 验收标准

- 页面内容区不再重复“管理概览”。
- 首屏风险区同时展示健康结论和首条待处理事项，并提供可点击处理入口。
- 刷新操作位于内容工具条，风险区不再以刷新作为主操作。
- 趋势和存储卡不再被 CSS 强制等高。
- 图表日期不低于 11px，自动化与活动辅助信息不低于 12px。
- 存储容量展示已用、总量和剩余量，并保留管理存储卷入口。
- 原有异常、空状态、刷新失败和下钻行为继续生效。
