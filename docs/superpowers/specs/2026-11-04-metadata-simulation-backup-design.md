# 订单备份元数据模拟模式设计

## 1. 目标

在本地 Windows 测试阶段，以线上真实的订单筛选范围和真实订单数量验证候选扫描、任务调度、订单清单读取、进度统计、失败重试和前端展示；不下载 COS 文件，但生成包含 manifest 和零字节占位文件的可下载模拟 ZIP，并持久化可查询的模拟快照证据。

## 2. 执行模式

- `REAL`：现有真实备份流程，下载文件、打包、持久化正式快照并提交线上回执。
- `METADATA_SIMULATION`：真实查询候选订单并逐单读取 Manifest，只生成隔离的模拟制品。
- 执行模式属于部署环境安全配置，只允许由环境变量控制，不进入可在页面修改的数据库业务配置。
- 环境变量：
  - `BACKUP_EXECUTION_MODE=REAL|METADATA_SIMULATION`，默认 `REAL`。
  - `BACKUP_SIMULATION_ROOT=D:/yigongbao-backup/simulation`。
  - `BACKUP_DEV_CANDIDATE_LIMIT=0` 表示不限制候选订单数量；正整数仅用于显式的小规模调试。
- `prod` Profile 启动时若检测到模拟模式必须直接拒绝启动，避免生产环境误用。

## 3. 模拟执行流程

1. 定时任务按“备份 X 天前的订单”、自然日截止时间、增量游标和正式订单过滤规则查询全部符合条件的订单。
2. 创建一条真实持久化的 `ORDER_BACKUP` 任务，并把本轮执行模式固化到任务配置快照中；任务启动后不受环境变量临时变化影响。
3. 对每个订单调用线上 Manifest 接口，读取完整订单业务快照、文件类型、文件关系、文件大小及预签名地址元数据。
4. 不访问任何预签名下载地址，不执行容量预留，不下载 COS 对象；生成模拟 ZIP，但该 ZIP 只包含 manifest、模拟摘要和零字节占位文件。
5. 在模拟根目录创建：`{taskDate}/{jobNo}/{orderNo}-{orderId}/`。
6. 每个订单目录生成：
   - `manifest.json`：线上返回的完整 Manifest。
   - `_simulation.json`：任务、订单、预计文件数、预计容量、模拟时间和模式等摘要。
   - 文件占位符：按资产文件名创建零字节文件；重名时加入资产 ID，且必须防止路径穿越。
   - ZIP：提交到热备 ArtifactStore，使用与真实备份一致的订单包存储键，供订单文件页下载验证。
7. 逐订单更新任务订单明细和任务统计。Manifest 获取或本地模拟制品生成失败时，沿用订单级重试策略。
8. 所有订单结束后任务进入终态；允许部分失败，并保留可重试、可取消和重启恢复能力。

## 4. 强制安全隔离

模拟模式必须保证：

- 不调用 COS 预签名 URL，不产生对象下载流量。
- 不执行容量预留。
- 不调用 Manifest 确认接口。
- 不提交线上备份回执。
- 不写入 `REAL` 正式订单证据，不提交线上回执；本地会写入 `METADATA_SIMULATION` 标记的快照、资产、关系和订单包记录。
- 模拟订单包可以标记为本地 `AVAILABLE` 以支持下载，但快照状态为 `SIMULATED`，并且恢复入口和后端恢复处理器均拒绝该模式。
- 不改变线上 `alreadyBackedUp` 判断，不获得 COS 清理资格。
- 不触发恢复、清理或其他线上写操作。

必须用自动化测试验证上述协作者在模拟模式下调用次数均为零，不能只依赖代码分支人工检查。

## 5. 状态与统计

- 任务记录持久化执行模式，接口返回 `executionMode`。
- 模拟订单成功状态使用 `SIMULATED`，失败状态使用 `SIMULATION_FAILED`。
- 模拟任务仍使用现有任务状态机完成调度和终态流转；前端根据模式将成功终态展示为“模拟完成”。
- 统计至少包括：真实订单总数、Manifest 成功数、Manifest 失败数、预计文件总数、预计文件总容量、已处理订单数。
- 模拟文件统计表示“Manifest 中预计文件”，前端必须标注为模拟占位文件，不能误显示为已下载真实文件。

## 6. 前端表现

- 模拟任务与真实任务统一出现在“订单备份”页面，使用明显的“元数据模拟”标签。
- 列表展示执行模式、订单总数、Manifest 成功/失败、预计文件数和预计容量。
- 详情展示完整订单核心业务字段、逐订单模拟状态、预计文件数/容量、模拟目录和失败原因。
- 模拟快照可以进入“订单文件”页面用于查询和下载验证，但必须显示“模拟备份”标识，并禁用线上恢复。

## 7. 验收标准

- 在候选订单数量不固定的情况下，可完整创建一轮覆盖全部符合日期条件订单的模拟任务。
- 任务可以跨进程重启续跑，最终状态和统计正确。
- 模拟根目录结构及 JSON/零字节占位文件正确。
- 测试期间 COS 下载、线上确认、线上回执次数均为零；本地模拟证据和可下载 ZIP 写入次数与成功订单数一致。
- 关闭模拟模式后，同一批订单仍可被正式备份流程选中。
- 前端能明确区分模拟结果和真实备份结果。
