## 3. 数据库迁移和查询计划

验证过程使用随机名称 `yigongbao_overview_verify_<随机值>` 创建临时库，并执行以下步骤：

1. 从基线提交读取一体化初始化脚本，建立迁移前结构；
2. 执行 `2026-11-11-13-admin-overview-dashboard.sql`；
3. 核对 `capacity_observed_at` 和 6 个 `idx_*_overview` 索引；
4. 对副本候选、每日任务结果、每日新增容量、近期任务执行 `EXPLAIN ANALYZE`；
5. 删除本次创建的临时库，未修改现有业务库。

结果：字段数为 1、概览索引数为 6。副本候选在数据库内按订单包聚合副本可读性、预期离线和元数据质量，只向 JVM 返回每包一行；本机现有 50 个正式包的 `EXPLAIN ANALYZE` 实测聚合约 0.405 ms。趋势查询使用概览索引过滤正式快照；近期任务先物化最多 10 条任务，再仅聚合这些任务的订单结果，避免每次首页刷新全表汇总所有历史任务订单。并发强制刷新使用单飞结果共享，不会让等待请求逐个重复执行全套查询。

最终副本候选 SQL 与数据质量聚合 SQL 在本机 MySQL 8.0.45 业务库再次执行 `EXPLAIN`，均成功生成执行计划。数据质量聚合固定为单行结果，覆盖正式快照关联模拟包、正式包完成时间缺失及活动副本引用卷缺失。

## 5. 无外部 I/O 与一致性审查

- `AdminOverviewController` 只依赖概览编排服务，不直接依赖存储探针、文件系统、Marker 或线上客户端。
- 概览服务只读取数据库事实、运行时配置快照和同步检查点；容量由成功探测时持久化的快照提供。
- 下载/恢复副本选择、备份预检、活动卷选择和首页投影复用 `StorageVolumeAccessPolicy`，避免建立第二套可读性判断。
- 封存历史按 `bk_volume_archive` 事实读取，不由卷当前 HOT/COLD 状态反推。
- 首页接口为只读 GET，不写审计日志，也不执行切卷、恢复、清理或同步操作。
